## 2. Основное назначение программы

**My Cube** — веб-приложение для тренировки и проведения соревнований по сборке кубика Рубика в 3D с поддержкой:

- 🎮 **Личные тренировочные попытки** (single mode)
- 🏠 **Комнаты и лобби** (casual и ranked матчи)
- ⚡ **Реалтайм матчмейкинг** (рейтинговая очередь, 1v1 соревнования)
- 🎨 **3D-рендеринг куба** с поддержкой различных скинов (Classic, Lantern, Spheres, Water Core, Magic 8-Ball)
- 📊 **Рейтинговая система** (ранжирование игроков, лидерборд)
- 👤 **Профили пользователей** (аватары, статистика, достижения)
- 🔐 **Аутентификация и авторизация** (регистрация, вход, роли: player, spectator, organizer, developer)

## 3. Необходимые зависимости

### Backend зависимости

Файл: [backend_repo/requirements.txt](backend_repo/requirements.txt)

```
Django==5.2                           # фреймворк
psycopg[binary]==3.2.1                # драйвер PostgreSQL
Pillow==11.1.0                        # обработка изображений (аватары)
channels==4.1.0                       # WebSocket поддержка
daphne==4.1.2                         # ASGI сервер для Channels
whitenoise==6.7.0                     # обслуживание статических файлов
prometheus-client==0.21.0             # метрики мониторинга
```

### Frontend зависимости

Фронтенд реализован на **Django templates + ванильный JavaScript** без build-системы.

**Требуемые компоненты:**
- Django templates (встроены в backend)
- JavaScript (ES6+, встроен в HTML файлы)
- Three.js (для 3D-рендеринга) — подключен через CDN в шаблонах
- Импортмапы для модульных JS-скриптов (importmap в base.html)

### Система окружения

- **Python:** 3.11
- **База данных:** PostgreSQL 14+ (порт 5433 по умолчанию)
- **Docker:** (опционально) Docker Engine, Docker Compose для контейнеризации
- **Node.js:** Не требуется (frontend использует ванильный JS)

## 4. Пошаговая инструкция запуска локально

### Вариант A: Локальный запуск (без Docker)

#### Шаг 1. Подготовка PostgreSQL

```bash
# 1.1 Убедитесь, что PostgreSQL 14+ установлена и запущена на порту 5433
# 1.2 Создайте базу данных (в psql консоли):
psql -h localhost -p 5433 -U postgres -d postgres -c "CREATE DATABASE my_cube;"

# 1.3 Проверьте подключение:
psql -h localhost -p 5433 -U postgres -d my_cube -c "SELECT 1;"
```

Значения по умолчанию (см. [config/settings.py](backend_repo/config/settings.py)):
- БД: `my_cube`
- Пользователь: `postgres`
- Пароль: `postgres`
- Хост: `localhost`
- Порт: `5433`

#### Шаг 2. Настройка Python окружения

```powershell
# Перейти в папку backend
cd backend_repo

# Создать виртуальное окружение
python -m venv .venv

# Активировать виртуальное окружение (Windows PowerShell)
.\.venv\Scripts\Activate.ps1

# Или для cmd:
.\.venv\Scripts\activate.bat
```

#### Шаг 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

#### Шаг 4. Миграция базы данных

```bash
python manage.py migrate
```

#### Шаг 5. Создание суперпользователя (опционально)

```bash
python manage.py createsuperuser
```

#### Шаг 6. Сбор статических файлов

```bash
python manage.py collectstatic --noinput
```

#### Шаг 7. Запуск сервера

```bash
python manage.py runserver
```

**Результат:** Приложение доступно по адресу `http://127.0.0.1:8000/`

**Проверка функциональности:**
- `/dashboard` — дашборд пользователя
- `/rooms` — список комнат
- `/ranked` — рейтинговые матчи
- `/profile/<username>` — профиль пользователя

### Вариант B: Запуск через Docker Compose (рекомендуется)

#### Шаг 1. Проверка структуры папок

```
my_cube_split/
  ├── frontend_repo/
  │   ├── templates/main/
  │   └── static/main/
  └── backend_repo/
      ├── Dockerfile
      ├── docker-compose.yml
      └── requirements.txt
```

#### Шаг 2. Запуск контейнеров

```bash
cd backend_repo
docker compose up --build
```

**Что поднимается:**
- **Django приложение** → `http://localhost:8000/`
- **PostgreSQL** → порт 5433 на хосте
- **Prometheus** (мониторинг) → `http://localhost:9090/`
- **Grafana** (дашборды) → `http://localhost:3000/` (логин: admin, пароль: admin)

#### Шаг 3. Проверка статуса

```bash
# Посмотреть логи
docker compose logs -f web

# Проверить здоровье контейнеров
docker compose ps
```

#### Шаг 4. Остановка

```bash
docker compose down
```

Для удаления данных БД:
```bash
docker compose down -v
```

## 5. Оценка сложности проекта, ограничения и улучшения

### 🔴 Общая сложность: **Высокая/Продвинутая**

#### Основные элементы сложности:

1. **Архитектура и реалтайм:**
   - Интеграция Django + Channels (WebSocket асинхронность)
   - ASGI сервер (Daphne) вместо традиционного WSGI
   - Синхронизация состояния в реальном времени между клиентами

2. **3D-рендеринг:**
   - Модульный RenderEngine для поддержки множества скинов
   - Three.js интеграция для клиентской 3D графики
   - Управление состоянием куба и синхронизация между браузерами

3. **Бизнес-логика:**
   - Алгоритмы матчмейкинга и рейтинговой системы
   - Обработка игровых событий и состояний комнат
   - Расчёт позиций в лидерборде (dense rank)
   - Управление присутствием пользователей

4. **Масштабируемость и мониторинг:**
   - Prometheus метрики для отслеживания производительности
   - Grafana дашборды для визуализации
   - Multi-container Docker архитектура

---

### 📋 Текущие ограничения:

| Ограничение | Описание |
|---|---|
| **Хранилище состояния куба** | Состояние куба хранится в памяти сервера (`ROOM_STATE`), что ограничивает масштабирование при несколько сервера |
| **Синхронизация реалтайма** | В случае перезагрузки сервера, история событий комнаты теряется |
| **Аутентификация WebSocket** | Полагается на сессионные куки; нет явного refresh-механизма для долгоживущих соединений |
| **Сложность моделей** | Модели БД (`UserProfile`, `Room`, `PublicRecordAttempt`) могут требовать оптимизации индексов при масштабировании |
| **Frontend версионирование** | Фронтенд хранится в отдельном repo и монтируется в Docker; сложнее управление версионами |
| **Тестовое покрытие** | Требуется расширение тестов для WebSocket логики и игровых сценариев |

- ✅ **Улучшить тестовое покрытие** — особенно для WebSocket consumers и game logic

- 🔄 **Мобильная оптимизация** — адаптивный дизайн, поддержка мобильных браузеров
- 🔄 **Социальные функции** — чат в комнатах, друзья, система уведомлений

#### **Долгосрочные (год):**

- ⭐ **Оффлайн режим** — progressive web app (PWA) с синхронизацией

#### **Операционные улучшения:**

- 📊 **CI/CD pipeline** — GitHub Actions для автоматического тестирования и деплоя
- 📊 **Backup стратегия** — регулярные резервные копии БД
